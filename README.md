# MiniGPT — Local AI Language Model

A small GPT-style language model built from scratch using PyTorch.
Trained locally and on Google Colab, with a retrieval-augmented chatbot, a calculator, and a full training pipeline.

---

## What This Project Is

This is a personal AI project that builds a miniature GPT model step by step — from a raw character-level model trained on a handful of QA pairs, all the way to a BPE-tokenized Transformer trained on real internet text from FineWeb-Edu.

The goal is to understand how language models actually work by building one, not just using one.

## Model Architecture — MiniGPTv2

A decoder-only Transformer (GPT-style) implemented from scratch in PyTorch.

| Component | Value |
|---|---|
| Architecture | Decoder-only Transformer |
| Parameters | ~1.3 million |
| Embedding dim | 128 |
| Attention heads | 4 |
| Transformer layers | 4 |
| Context length | 256 tokens (128 for QA-only runs) |
| Tokenizer | BPE (Byte-Pair Encoding), vocab size 2000 |
| Activation | GELU |
| Normalization | Pre-LayerNorm |

## How to Run

### 1. Set up the environment

```bash
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 2. Chat with the model

```bash
python src/chat.py
```

Loads the best available checkpoint automatically in this order:
`my_minigpt_v3.pth` → `my_minigpt_v2.pth`

### 3. Use the RAG chatbot (no model needed)

```bash
python src/rag.py
```

Answers questions from a built-in knowledge base using TF-IDF retrieval.
Also handles arithmetic: `"10 divided by 2 plus 1"` → `"6"`

### 4. Verify the pipeline before training

```bash
python verify_v3.py
```

Runs 52 checks — imports, path safety, checkpoint integrity, calculator, RAG — without downloading anything or training.

### 5. Train a new v3 model locally

```bash
python src/train_v3.py
```

Prompts before overwriting any existing file. Never touches v1/v2 checkpoints.

## Training on Google Colab (Recommended)

Open `colab_train_v3.ipynb` in [Google Colab](https://colab.research.google.com).

Set runtime to **T4 GPU** → Run all cells.

The notebook:
- Requires no file uploads — everything is written inline
- Builds a QA-only corpus (51 pairs × 500 repetitions) with `[EOS]` stop tokens
- Trains a BPE tokenizer from scratch on that corpus
- Trains MiniGPTv2 for 5,000 steps (~2-3 minutes on T4)
- Saves periodic checkpoints every 1,000 steps
- Verifies the checkpoint/tokenizer pair before download
- Downloads both files directly to your browser

After downloading, place the files in:
```
checkpoints/my_minigpt_v3.pth
tokenizers/my_bpe_tokenizer_v3.json
```

## Key Design Decisions

**Why QA-only training first?**
Mixing 51 QA pairs against 12M characters of FineWeb creates a 170:1 ratio. The model learns the `User:/Assistant:` format but cannot reliably match questions to answers. Training on QA pairs alone first confirms the architecture can memorise the mappings before general text is added.

**Why `[EOS]` tokens?**
Without an explicit stop signal, the model bleeds into the next conversation turn. Adding `[EOS]` after each assistant answer gives the model a clear target to stop at.

**Why BPE over character-level?**
Character-level tokenizers require the model to learn spelling from scratch. BPE compresses common subwords into single tokens, reducing sequence length and letting the model focus on meaning rather than characters.

**Why save tokenizer and checkpoint together?**
A model trained with one tokenizer produces garbage output when loaded with a different one — even if the vocab sizes happen to match. The v3 checkpoint stores `tokenizer_file` in its metadata so the pairing is always explicit and verifiable.

## RAG Knowledge Base

`src/rag.py` contains a built-in knowledge base of 71 QA pairs covering:
- AI, machine learning, neural networks, Transformers
- Python, Java, PyTorch, APIs
- General science (gravity, water cycle, photosynthesis)
- Geography, history, arithmetic
- Chatbot identity questions

Features:
- TF-IDF similarity retrieval (no embeddings needed)
- Query normalization: `"javaaaaaa"` → `"java"`, `"j a v a"` → `"java"`
- Alias table: `"tramp"` → `"trump"`, `"phyton"` → `"python"`
- Calculator integration: routes math questions to a safe AST evaluator
- Admits when no reliable match is found (threshold=0.25)

## Calculator

`src/calculator.py` safely evaluates arithmetic from natural language:

```python
calculate("10 divided by 2 plus 1")  # "6"
calculate("(10 + 2) * 3")            # "36"
calculate("5 / 0")                   # None  (division by zero handled)
calculate("what is python")          # None  (not a math question)
```

Uses Python's `ast` module — no `eval()`, no code injection risk.

---

## Safety Features

- `train_v3.py` maintains a `_PROTECTED` set — any attempt to write a v1/v2 file triggers `sys.exit()`
- Both output files are guarded with an overwrite prompt before any work starts
- `chat.py` detects v1 architecture checkpoints and refuses to load them
- `chat.py` detects vocab mismatches and warns clearly instead of silently generating bad output
- `verify_v3.py` checks sha256 hashes of all backup files to confirm nothing was accidentally overwritten
